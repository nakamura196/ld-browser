About this tool

Musubi takes a URI, fetches the RDF describing that resource directly from your browser, and shows it as a table and a graph. Click a link to follow it to the next resource.

Normally no server

Fetching and display normally happen in the browser of whoever is looking, so load does not concentrate anywhere as more people use it.

A browser can only read sites that allow cross-origin requests (CORS). The same applies if one step of a redirect (301, 303) lacks the permission.

For a few sources without the permission, such as the National Diet Library authorities, Musubi goes through a relay server (Vercel). It is used only after a direct fetch fails, and the page says so. Other sources without the permission show "Could not load".

Supported formats

  • Turtle, N-Triples, N-Quads, TriG, JSON-LD, RDF/XML
  • JSON-LD (<script type="application/ld+json">), microdata and RDFa embedded in HTML pages

Documents over 2 MB are not read.

Rewriting

For Wikidata URIs, the light Turtle version (Special:EntityData/…​.ttl?flavor=simple) is fetched. http:// URIs become https://. For vocabularies such as SKOS and Dublin Core, where a redirect step loses the permission, the final target of the redirect is fetched directly.

The name

Musubi (結び, "tying together") is a tool for following the ties between data. Until November 2026 it was called LD Browser and lived at browser.ldas.jp. It shares its look with Kasane for IIIF images and Awase for TEI transcriptions.

Inspiration

Learned from LD Browser (2014) by Masahide Kanzaki. His version fetches through a server and, as of October 2026, is down because of heavy traffic.
